Principal Engineer — Hiring Manager interview.

Highest priority: genuine agentic coding, not autocomplete. Be ready to say years of hands-on use, tools (Claude Code, Cursor, Copilot, similar), how you turned agents into repeatable workflows/patterns for a team, what improved (speed, quality, tests, review), and how you kept review, tests, security, and a human in the loop. Do not say “I use Cursor to write code.” Give one concrete example: problem, approach, tools, workflow, measurable outcome.

Also expect: scalable systems and HA in public cloud (horizontal vs vertical, load balancing, fault tolerance, observability, DR, cost, bottlenecks) with a real production story. Hands-on AWS and/or GCP (and Azure if true): years, services, whether you designed vs maintained, deploy, network, security, data, compute, storage, scale. Production TypeScript, React, Next.js: architecture, APIs, performance, state, tests, deploy, large codebases. Full-stack ownership: frontend, backend, APIs, DB, infra, CI/CD, monitoring — design through production. Comfort across languages: Python (pipelines/APIs), PHP/Laravel or legacy; fundamentals over polyglot trivia; when to refactor vs live with it. Architecture ownership: why this shape, alternatives, reuse, debt, short-term vs long-term, influence, disagreement. Cloud migration if you have one: from/to, your role, data, downtime, security, validation, outcome. Data/analytics is nice-to-have: pipelines, ETL/ELT, quality, scale. Leadership without title: standards, mentoring, consensus, clear talk with Product/Design/Data.

When they ask for experience, answer as: context, what YOU owned, approach, why, what was hard, outcome, a number if the resume has one. Stay in first person. Do not invent tools, companies, or metrics that are not in the resume. If the resume is thin on agentic coding, say the real years and the real workflow — do not fake Claude Code years.
